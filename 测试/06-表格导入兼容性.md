# 06 表格导入兼容性

> 用途:外部导入的 Markdown 表格写法差异很大。本节覆盖 **GFM 规范允许、但旧版本识别不了** 的写法\(单横线分隔、省略首尾竖线、表格打断段落、容器内表格等)。**预期**:全部渲染为表格;首次保存后归一化为标准 GFM\(三横线 + 首尾竖线),之后往返稳定、不再变长。

## 6\.1 单横线分隔行\(回归重点)

| # | 目标 | 落位 | 日耗时 |
| :--- | :--- | :--- | :--- |
| 1 | 英语大量阅读 | 课堂隐藏阅读 + 晚自习② | 60min+ |
| 2 | 词汇汇总 | 体育课\(周一移至晚间) | 15min |

**预期**:这是合法的 GFM 表格 —— 分隔行单元格只要求至少一个 `-`。旧解析器要求 ≥3 个横线,会把整张表当成带 `|` 的普通段落显示。

## 6\.2 双横线 / 省略首尾竖线 / 首尾不一致

| 双横线 | 表格 |
| :--- | :--- |
| a | b |

省略首尾竖线:

| a | b |
| :--- | :--- |
| 1 | 2 |

首尾竖线不一致:

| c | d |
| :--- | :--- |
| 3 | 4 |

**预期**:三种写法都渲染为表格\(保存后统一补成首尾竖线 + 三横线的标准形态)。

## 6\.3 表格紧接在段落文字后

计划如下\(下一行没有空行):

| 任务 | 时间 |
| :--- | :--- |
| 背单词 | 15min |

**预期**:GFM 允许表格打断段落,文字独占一段,整张表正常渲染。

## 6\.4 单列表格与对齐写法

| 单列 |
| :---: |
| 居中单元格 |

**预期**:单列表格渲染为单行表头加数据行;`:-:` 居中对齐生效。

## 6\.5 容器内的表格

- 列表项里的表格:
  | 名称 | 数量 |
  | :--- | :--- |
  | 甲 | 1 |

> 引用里的表格:
> | 名称 | 数量 |
> | :--- | :--- |
> | 乙 | 2 |

**预期**:列表项与引用内都能渲染表格。

## 6\.6 单元格里的转义管道

| 表达式 | 说明 |
| :--- | :--- |
| a \| b | 字面管道 |

**预期**:单元格显示 `a | b`,不被拆成两格,保存时反斜杠不逐轮翻倍。
