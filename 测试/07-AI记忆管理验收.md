# 07 AI 记忆管理验收

> 用途:验收 v4.2.0 新增的「设置 → 记忆管理」。本文件只描述**在界面上操作**的步骤,数据始终留在本机:桌面端存放在 `~/.unidoc/ai_memory.json`,Web 端存放在 localStorage 的 `unidoc-ai-memory`。**预期**:每一步都符合该节标注的「预期」;任一步不符时记录实际现象即可。

## 7.1 设置入口与总览

1. 打开 **设置**,在左侧导航点击 **记忆**(位于 AI 之后);也可以从 AI 设置里的「记忆管理」卡片点 **管理记忆** 进入。
2. 查看顶部摘要行:记忆条数、置顶 / 停用数量、容量进度与最近更新时间。
3. 滚动到底部,点击存储位置旁的 **复制** 按钮。

**预期**:入口可见且可切换;数字与实际数据一致;空数据时显示 0 条而不是空白;存储路径可复制,桌面端为 `~/.unidoc/ai_memory.json`,Web 端为 `localStorage · unidoc-ai-memory`;记忆文件损坏时显示错误提示与「重试」,确认后可放弃损坏文件并重新开始;界面上不出现数据版本 / 迁移类提示。

## 7.2 用户画像

| 字段 | 填写示例 | 预期 |
| --- | --- | --- |
| 姓名 | 张三 | 保存后总览的画像字段数 +1 |
| 别称 / 称呼 | 老张、Z | 标签形式展示,可删除 |
| 写作风格 | 简洁直接,多用列表 | 以文本展示 |
| 格式偏好 | Markdown 表格 | 标签形式展示 |
| 关注主题 | 产品设计 | 标签形式展示 |
| 技术栈 | Vue 3、TypeScript、Rust | 标签形式展示 |
| 备注 | 正在准备考试 | 以文本展示 |

填写全部字段后点 **保存画像**,再点开「用户画像（可选）」卡片,点 **清空** 并确认。

**预期**:保存后画像卡片标题摘要显示姓名或「N 个字段已填写」,刷新或重开设置页仍在;清空只移除画像,记忆条目不受影响;清空操作有确认弹窗(标题为「清空用户画像」);标签支持回车添加、点 × 删除并自动去重。

## 7.3 记忆事实的增删改查

1. 点 **新增记忆**,填写内容(例如「我的项目叫 Alpha,是一个文档编辑器」)、分类 **项目背景**、标签 `项目`、重要度拖到 **高**,保存。
2. 用搜索框输入 `Alpha`,再用分类筛选切换「全部 / 个人信息 / 项目背景 / 知识储备 / 偏好设置 / 其他」。
3. 切换排序:「最近更新 / 创建时间 / 重要度 / 访问次数」。
4. 对刚新增的条目依次执行 **置顶**、**编辑**(在弹窗中关闭「启用此记忆」观察效果后再打开)、**删除**。

**预期**:新增后列表立即出现该条并附带分类、标签、来源与相对时间;搜索与分类筛选只保留命中项;排序切换后顺序正确变化;置顶条目带标记且排在前面;停用后条目变灰并显示「已停用」标记,不参与检索;编辑弹窗预填原值,保存后内容与更新时间刷新;删除需确认,删除后提示里可 **撤销**。内容为空或超过长度上限时不能保存;与已有条目高度相似时先弹出「检测到相似记忆」的二次确认。**合并重复** 与 **清理低价值** 收入「更多」菜单,仅在存在可处理项时显示,清理先预览条数再确认删除。

## 7.4 开关是否生效

1. 先确认 **启用 AI 记忆** 与 **自动提取记忆** 均为开。
2. 与 AI 对话一轮,说出一个明确的新事实(例如「以后请叫我老王」),结束对话后回到设置页刷新列表。
3. 关闭 **自动提取记忆**,再对话一轮并说一个新事实,回来看列表。
4. 关闭 **启用 AI 记忆**,再向 AI 提问,并检查 AI 是否还能使用记忆相关工具(如 `save_memory`、`search_memory`)。

**预期**:第 2 步后列表新增一条来自自动提取的记忆(来源标注为自动提取);关闭自动提取后不再新增,但**已有数据保留**;关闭总开关后不再注入记忆、不再注册记忆工具、也不再自动提取,重新打开后一切恢复;自动提取结果可能不够精确,属启发式抽取的已知限制。

## 7.5 导出、导入与合并 / 替换

1. 点 **导出**,选择保存位置,保存为 `.json` 文件。
2. 打开导出的文件,确认结构。
3. 点 **导入**,选择刚导出的文件,选择 **合并**,确认预览信息后点 **开始导入**,查看完成提示中的新增 / 更新 / 跳过数量。
4. 再次导入并选择 **替换**。
5. 选中一个格式错误的 JSON 文件导入。

**预期**:导出文件可读,结构形如:

```json
{
  "format": "unidoc-ai-memory",
  "formatVersion": 1,
  "exportedAt": 1760000000000,
  "memory": {
    "version": 2,
    "profile": {},
    "facts": [],
    "settings": {
      "enabled": true,
      "autoExtract": true,
      "maxInjectFacts": 5,
      "maxFactChars": 500,
      "autoCleanup": true
    },
    "updatedAt": 1760000000000
  }
}
```

合并导入时按 id 更新、按内容跳过重复项,并显示新增 / 更新 / 跳过统计;替换导入前会先自动备份当前记忆,并弹出确认;导入非法文件时提示错误且**不修改**现有数据;导入后刷新页面数据仍在。

## 7.6 清空与撤销

1. 删除一条记忆后立刻点提示里的 **撤销**。
2. 点 **清空全部记忆**,在确认框中输入「清除」并确认。
3. 检查桌面端的备份文件是否生成。

**预期**:撤销后条目回到列表(排在末尾亦可),提示消失;清空全部记忆需输入「清除」二次确认,执行前自动备份到 `~/.unidoc/ai_memory.backup.json`(Web 端为 localStorage 的 `unidoc-ai-memory-backup`),随后画像与记忆事实全部清空、总览归零,而开关与注入上限等设置保留;重开应用后不会"复活"旧条目;备份失败不会阻塞清空,仅在控制台记录。

## 7.7 持久化与迁移

1. 桌面端打开 `~/.unidoc/ai_memory.json`,检查是否为合法 JSON 且含 `"version": 2`。
2. 修改任一记忆后等待约 1 秒再关闭应用(防抖保存),重开检查。
3. 用旧版 v1 数据(不含 `settings`)替换该文件后重开应用。
4. Web 端在浏览器开发者工具中检查 localStorage 的 `unidoc-ai-memory`。

**预期**:文件为明文 JSON,包含 `version`、`profile`、`facts`、`settings`、`updatedAt`;修改后约 1 秒落盘,直接关窗也会在关闭前强制保存一次;v1 数据被**静默**迁移到 v2(补齐默认设置、保留画像与事实),界面不展示迁移 / 版本提示,迁移前自动备份到 `~/.unidoc/ai_memory.backup.json`;Web 端持久化 key 为 `unidoc-ai-memory`,迁移备份 key 为 `unidoc-ai-memory-backup`。

## 7.8 深色主题

在设置中切到**深色**主题,逐项查看记忆管理,再切回**浅色**。

**预期**:记忆管理的卡片、输入框、按钮、标签、进度条与弹窗均跟随主题变量,无白底闪烁、无低对比度文字;深色下错误提示与危险按钮仍清晰可辨。

## 7.9 已知限制(不是 bug)

| 现象 | 说明 |
| --- | --- |
| 自动提取偶尔记偏或漏记 | 抽取基于关键词与模式规则,可关闭自动提取或手动修改 |
| 相近条目不会自动消失 | 需手动点「合并重复」 |
| 超过 200 条时低价值条目被淘汰 | 容量上限 200,置顶条目不参与淘汰 |
| 检索是关键词打分而非语义 | 换一种说法提问可能召回不到同一条记忆 |
